# France streaming TU recovery

The stripped French executable now compares all 19 `xstransvc.cpp` functions
(5,584 bytes), using the existing complete shared-source compilation. Normal
objdiff reports 14 functions / 2,820 code bytes matched, 97.53438% fuzzy. The

This remains a partial source comparison, with no complete-TU or retail-link claim.

## Original identity and boundaries

`tools/platforms/france_tu_sequences.py` authenticates all four originals and
reproduces the scoped registry in
`config/platforms/SLES-53623/tu-corroborated-functions.json`. It never reads a
compiled source object. The reviewed French sequence starts at `0x20ccd0`:
all 19 names, canonical overload identities, sizes and ordering agree across
the three debug-bearing retail DWARF originals. The complete sequence, including
zero alignment gaps, has one location in the French original for each reference.
Its longest unmodified search anchor is 368 bytes.

Every opcode, register operand, arithmetic immediate and relative branch is
preserved. The only permitted differences are actual J/JAL address operands and
LUI-derived absolute data operands. Each data half has a reaching LUI, no
intervening register clobber, and no direct branch bypass of the definition.
Annulled/call delay-slot definitions are rejected. A call between the halves is
allowed only when the low instruction is its immediate delay slot. All 64
changed data operands pass these checks against each debug original.

The original startup zeroing loop establishes the French BSS range despite its
stripped ELF omitting `p_memsz`. Streaming state and buffer addresses retain their
original relative zero-fill layout; the four initialized string addresses contain
the same complete strings. CPU and initialized-data regions are independently
regenerated by the existing original layout verifier.

Eighteen French bodies have closed local control flow, balanced frames, terminal
returns and zero following alignment. The remaining eight-byte function is a
direct tail wrapper to the preceding independently corroborated overload.
Seventeen entries have existing entry-rooted direct-call witnesses. The larger
overload is reached by that wrapper; shutdown additionally relies on its closed
body and unique position in the complete named sequence. There is no claim that
each body has a separate rooted direct caller.

All repeated direct destinations preserve one-to-one call relationships. Named
external callee bodies also retain their full instruction structure with checked
address operands. Unnamed runtime neighbors use only a compared 32-byte entry
prefix, not an invented function extent. These neighbors corroborate the unit;
they are not promoted as independently named relocation anchors.

unrestored. The normal project objdiff policy remains `functionRelocDiffs=none`;
code-score matching does not claim raw binary reconstruction or a complete link.
All five holdouts remain present in the comparison.

The genuine French production pipeline passes. All previous source-unit reports
are unchanged; only the new streaming unit and the unresolved-code remainder
change. Known functions increase from 331 / 90,040 bytes to 350 / 95,624 bytes,
while total CPU code stays 2,979,968 bytes and data stays 2,384,384 bytes.

No game source changes are included in this recovery.
