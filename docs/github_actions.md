# GitHub Actions

This fork builds independently of bfbbdecomp's infrastructure.

- Source: [zcanann/bfbb](https://github.com/zcanann/bfbb)
- Private toolchain and original executable: [zcanann/bfbb-build](https://github.com/zcanann/bfbb-build)
- Container: `ghcr.io/zcanann/bfbb-build:main`
- Progress: https://zcanann.github.io/bfbb/
- Runs: https://github.com/zcanann/bfbb/actions/workflows/build.yml

## Builds and reports

The Build workflow runs on pushes, same-repository pull requests, and manual dispatch.
It compiles all source objects, links the matching executable, verifies the retail
SHA-1, and generates the existing deduplicated objdiff report. The Actions job
summary shows matching and linked progress by category.

Each successful run uploads `GQPE78_report` (objdiff report, progress JSON, and
commit metadata) and `GQPE78_maps`. Main-branch builds also deploy the static
progress page and badge API to GitHub Pages. Branch and PR builds never deploy.
The page is generated by `tools/ci_progress.py`; it uses the report's existing
metrics without changing how matching is calculated.

The former upstream website deployment and PR-comment workflows are replaced
by these summaries and artifacts. No upstream website token, Discord webhook,
or external progress service is required.

## Private container access

Keep both the build repository and its GHCR package private. In the
[package settings](https://github.com/users/zcanann/packages/container/bfbb-build/settings),
grant `zcanann/bfbb` **Read** under **Manage Actions access**. The workflow uses
its short-lived `GITHUB_TOKEN` with `packages: read` to pull the image; no personal
access token or deploy key is needed.

Fork pull requests are skipped because the image contains the original game
executable. Review external changes before bringing them onto a branch in this
repository. Do not switch this workflow to `pull_request_target` to run external
code with private-image access.

Build outputs and original objects are not cached in public Actions caches.
Only the explicit report/map allowlist is uploaded, and the Pages directory
contains only HTML and report JSON. Never upload `orig/` or the entire `build/`.

## GitHub Pages

The repository's Pages build source must be **GitHub Actions**. The deploy job
uses the `github-pages` environment with `pages: write` and `id-token: write`.
Only `main` publishes to https://zcanann.github.io/bfbb/.

To regenerate the page locally after a build:

```sh
python tools/ci_progress.py build/GQPE78 --output build/progress-site
```

Open `build/progress-site/index.html` in a browser. To refresh the container,
push the private build repository's main branch or manually run its image workflow.
