What the labels mean

Verified payoff
A corrupt run beat a matched clean control in a measurable way.
Consumer verified
The desired game state does something useful, but no natural setup is known to create it.
Verified effect
The write visibly changes the game, without a demonstrated progression or time payoff.
Verified no payoff
The state changed, but a matched control showed no reward or progression advantage.
Load blocker / crash
The sequence does not reach controllable play under the tested conditions.
Candidate
Addresses and bytes intersect something interesting. Runtime behavior is not yet proven.

What is being varied?

A combo HUD animation can survive a title transition with a stale allocator pointer. Different source scenes and timing histories select different retained addresses. The destination then loads a new object or resource over that address, and a later HUD animation writes a fixed motive structure into it.

The catalog records the producer action, retained address, destination owner, overwritten C++ member, continuation safety, observed result, comparison control, and evidence path. GameCube has the deepest automation today; PS2 and Xbox use the same public result model while their runners catch up.
